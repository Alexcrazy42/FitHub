# Marketplace TODO: от старта до готового результата

Этот файл - рабочий чеклист для разработки marketplace в FitHub. Он специально разделяет backend и frontend, потому что эти части можно делать отдельными заходами. Порядок ниже ведет от минимального каталога к оплате, заказу и доставке.

Подробные проектные заметки лежат рядом:

- [README.md](README.md) - общий роадмап и архитектура.
- [Backend.md](Backend.md) - каталог, варианты, цены, остатки, фасеты.
- [Frontend.md](Frontend.md) - каталог, карточка товара, покупка варианта.
- [bankManager.md](bankManager.md) - оплата через BankManager.
- [delivery.md](delivery.md) - доставка и live-трекинг.
- [CourierSimulation.md](CourierSimulation.md) - симуляция курьеров.
- [Testing.md](Testing.md) - сложные сценарии тестирования.
- [Decisions.md](Decisions.md) - решения Этапа 0 до старта кода.

## Правило работы

- Делать этапы сверху вниз.
- Внутри этапа можно делать только backend или только frontend, если второй слой еще не готов.
- Если frontend делается раньше backend, использовать временный mock API в том же контракте, который потом будет отдавать backend.
- Если backend делается раньше frontend, закрывать этап через Swagger/HTTP-файлы/интеграционные тесты.
- Не переходить к следующему бизнес-этапу, пока не выполнен "Готово, когда" текущего этапа.
- Каждый этап считается закрытым если он сделан в соответствии с Backend.md
